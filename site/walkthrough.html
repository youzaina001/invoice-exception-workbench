Local PDF walkthrough

Use synthetic invoices only. The Operator reviews the original source and all five fields, explicitly confirms, and submits. This site's report and downloads need no account. Running the application additionally needs the source checkout and pinned Airflow core described in its README. The invoice repository is currently private and these changes are unpublished; no public source-download or working public replay is claimed.

Missing amount → checked case → corrected source

  1. From the source checkout, use make setup CORE=/path/to/airflow-dq-agent. Start bundled PostgreSQL with make db and the localhost application with make run, in separate terminals as the README explains.
  2. Upload missing_amount.pdf using PDF file → Review PDF. Compare the source text with all five fields. The absent amount must remain missing, not guessed.
  3. Choose Confirm reviewed PDF, then Submit confirmed PDF. Run checks on the current submission. Actual amount-completeness evidence creates an open case.
  4. Return to the PDF draft and use Replace PDF source with corrected_amount.pdf. Review the corrected text. The replacement clears confirmation.
  5. Confirm and submit the corrected revision. Run fresh checks, then explicitly choose Resolve case. Earlier checks cannot authorize the new source, and passing checks alone does not silently resolve the case.

Original PDF bytes, page text, extraction identity, revisions and confirmations remain in local PostgreSQL. Edits and replacement sources need new confirmation. Missing or ambiguous invoice ID, supplier ID, date or currency refuses intake; missing or ambiguous amounts can open a real case. Scans, malformed/oversized PDFs and multiple invoices are outside this bounded text-PDF path.

Replay the development report offline

After source setup, run this from the Invoice Triage checkout. It needs no model credentials or hosted account. Use fresh output/work paths each time; the isolated PostgreSQL cluster stops and its evidence directory remains.

.venv/bin/python -m invoice_triage.workflow_replay \
  fixtures/extraction/development/manifest.json \
  --plan fixtures/extraction/development/workflow.json \
  --workdir /tmp/invoice-replay-new \
  --output /tmp/invoice-report-new.json

Read the saved report or download the full synthetic JSON. Raw extraction and actual confirmed outcomes are separate. Both arms use the same gate. Scripted correction follows a frozen policy; labels score outcomes afterward. Each arm/document has an isolated database and the installed core runs in-process. No user's workbench database is reset.

These outputs are authored examples. Their original bytes remain unchanged. No independently held-out result or live billing proof is available. Actual billed cost and human review time are unavailable; replay is not fresh provider integration.

Preserved CSV journey

Download missing_amount.csv and corrected_amount.csv. Ingest the missing-amount CSV, run checks, ingest the correction for the same invoice, run checks again, then explicitly resolve the case.

Original CSV bytes are not retained; uploads are parsed into rows. This differs from the local PDF evidence retained with drafts and submissions.

Separate hosted CSV behavior

Hosted acceptance is unverified. In the implemented hosted CSV design, only an invited Reviewer enters. The Maintainer creates invitations in the Clerk dashboard; the provider sends invitation mail. The application has no invitation UI, public registration or application mail service.

First sign-in creates a Demo Workspace and empty Demo Attempt. Signing out and returning resumes it. Start fresh creates a new empty attempt and keeps the previous attempt, including audit evidence, as read-only history. Ingest and resolve against past attempts are refused. A workspace keeps at most five attempts; a sixth removes the oldest in that workspace, without changing another Reviewer's records.

Local PDF retention does not establish hosted PDF retention. Hosted PDF routes are disabled. The €0 hosting boundary and historical provider assumptions remain separate from the finite extraction allowance.
